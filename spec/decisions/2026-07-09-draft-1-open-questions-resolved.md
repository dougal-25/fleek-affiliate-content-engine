# 2026-07-09 — Draft 1's open questions, resolved

Draft 1 of the case-study approach left six questions marked open. This record closes them. Lifted out of
`deliverables/case-study-approach.md` §0, where they were cluttering a document meant to describe the plan
rather than its history.

| Open question (draft 1) | Decision |
|---|---|
| Build a wiki knowledge base of resellers before doing anything? | **Yes.** Phase 0, timeboxed to half a day. Lives in the `Fleek Wiki/` Obsidian vault. Built by a research agent (Claude Code + Perplexity). Feeds keywords, scoring, personalisation. It is a *means*, not the deliverable. |
| Shortlist on Airtable/Sheet, then a card-form dashboard? | **Airtable is the single source of truth.** Gallery view = the creator cards. No custom dashboard for v1 — Airtable Interfaces gives the "ecosystem dashboard" look in minutes. A custom Vercel dashboard is a stretch goal only. |
| Dashboard should surface creator groups we didn't know existed, and keep up with trends | Enrichment tags every creator with content keywords → grouping by tag in Airtable surfaces emergent segments ("sourcing-trip vloggers", "Vinted flippers", "wholesale educators"). The wiki gets a monthly trends refresh. |
| Should the recruitment funnel be built into the ecosystem dashboard, or alongside it? | **Built in.** The funnel is a Kanban view of the same Airtable base, grouped by Stage. One database, three views (cards / kanban / scores). Say that line in the presentation — it lands as systems thinking. |
| Scoring framework — how and why do we build it? | Full methodology in `deliverables/case-study-approach.md` §7: factors chosen for signal on "will this creator drive reseller signups at low CAC", weights justified, calibrated against known-good archetypes, re-weighted from funnel data. That feedback loop *is* the rich factoring system. |
| Briefs — where hosted? Must be automated and scaled | Generated by the existing `content_brain` engine from the creator's Airtable record → written back to the record + auto-published as a shareable Notion page. Trigger = stage change to Onboarded. One click per creator, batchable. |

**Also decided:** the live demo is this repo — `python run_campaign.py brief CRE-0042` in a terminal — not a
Replit scratch project. It already exists, and it's true to the stack.
